# Конфигурация

Все ключи `config.json` со значениями по умолчанию, по секциям.

|---|---|---|

| `multiMessage` | `true` | Разрешить 2–3 сообщения подряд |

Отсутствующий ключ считается включённым. Требует `vision` и `mediaDescriptions`; один дополнительный запрос к описателю на картинку, в рамках `media.maxPerTurn` |
| `videoDescriptions` | `false` | Смотреть короткие видеоклипы через модель с поддержкой видео; требует также включённого `mediaDescriptions`. Включается в `config.local.json`; также нужна модель с поддержкой видео и, для ссылок на видеосайты, `yt-dlp`/`ffmpeg` |

| `imageRelook` | `true` | При обращении к персонажу посмотреть на картинку ещё раз, чтобы ответить на вопрос или проверить утверждённую деталь; требует `vision`. Делит дневной счётчик `media.video.rewatch.maxPerDay` с повторными просмотрами видео. Отсутствующий ключ считается включённым |
| `webLookup` | `false` | Читать ссылки, опубликованные в чате, и искать в интернете, когда задан фактический вопрос. В отличие от остальных переключателей, отсутствующий ключ считается ВЫКЛЮЧЕННЫМ. Для поиска нужен `BRAVE_SEARCH_API_KEY` в `.env`; без него работает только чтение ссылок. См. [Медиа: ссылки и поиск](media.md#ссылки) |
| `imageGeneration` | `false` | Разрешить персонажу рисовать картинки через подпроцесс рисования. Отсутствующий ключ считается включённым. Включается в `config.local.json`; нужна модель с поддержкой генерации изображений в `roles.drawing`. См. [Медиа: рисование](media.md#рисование) |
| `privateMessages` | `false` | Отвечать на личные сообщения от участников сервера. Требуется сохранённый публичный профиль и `affinity.score >= private.minAffinity`. См. [Сообщения и память: приватный слой](messages-and-memory.md#приватный-слой) |
| `privateLikeServer` | `true` | Приватный чат работает как серверный канал: классификатор маршрута, подтягивание каналов, серверный поиск (recall) и эпизоды упоминаемых участников работают в ЛС. Канал подтягивается в ЛС только если собеседник имеет право View Channel на нём. Отсутствующий ключ считается включённым. `false` возвращает прежнее поведение ЛС (без подтягивания, маршрута, поиска и эпизодов) |
| `channelPull` | `true` | Подтягивать другой канал в запрос хода, когда последние сообщения или триггер содержат реальное упоминание канала. Отсутствующий ключ считается включённым. См. `context.pull.*` |
| `elsewhere` | `true` | Отвечать на вызов (@упоминание, ответ, имя) из канала, где бот может читать, но не писать. Ответ идёт в первый подходящий канал из `memory.mainChannelIds`. Отсутствующий ключ считается включённым |
| `portraitRefresh` | `true` | Обновлять портрет участника по счётчикам сообщений на периодическом расписании. Отсутствующий ключ считается включённым |
| `notesRefresh` | `true` | Периодически перепроверять заметки каналов и сервера по размазанной выборке недавних сообщений. Отсутствующий ключ считается включённым. См. `memory.notesRefreshDays*` и [Прогрев: Актуализация заметок](warmup.md#актуализация-заметок) |

## `llm`

| Ключ | По умолчанию | Описание |
|---|---|---|
| `baseUrl` | `"https://openrouter.ai/api/v1"` | Эндпоинт chat completions |
| `temperature` | `1` | Температура сэмплирования |
| `maxOutputTokens` | `2000` | Макс. токенов на выходе |
| `maxRequestTokens` | `50000` | Жёсткий лимит токенов на запрос |
| `safetyMargin` | `0.9` | Доля `maxRequestTokens`, доступная бюджету |
| `timeoutMs` | `300000` | Таймаут запроса (мс) |
| `probeTimeoutMs` | `30000` | Таймаут пробы каждой модели в карточке `/nep status` владельца (мс) |
| `helperTimeoutMs` | `30000` | Таймаут для помощника, работающего параллельно с ходом (классификатор маршрута, классификатор поиска и сводка recall). Помощник, не уложившийся в это время, отбрасывается; ход продолжается без его результата |
| `retries` | `2` | Повторы при временных HTTP-ошибках (408/429/5xx) и сетевых сбоях. Дневная квота аккаунта провайдера (429) не повторяется: одна попытка, затем ошибка |
| `maxRequestsPerDay` | `5000` | Дневной лимит запросов |
| `provider` | `null` | Объект маршрутизации OpenRouter `provider`, передаётся как есть; `null` = поле не отправляется |
| `providerByModel` | `{}` | Маршрутизация по модели; подробности ниже |
| `cache.ttl` | `"1h"` | TTL кэша, отправляемый с маркером: `"1h"` или `"5m"` |
| `cache.profilesTtl` | `"1h"` | TTL кэша отдельного маркера на профилях (`<people>`) в пользовательском сообщении ответа: `"1h"` или `"5m"`; `null` или `false` = без маркера. Не длиннее `cache.ttl` (`"5m"` в `cache.ttl` делает и это `"5m"`) |
| `cache.roles` | `["voice"]` | Роли запросов, чьё системное сообщение (и, для ответа, стабильный пользовательский префикс и профили) получает маркер кэша. Запросы memory-voice исключают себя, поэтому кэшируется только ответ. Добавьте `analyzer` и `reasoner` для кэширования стабильных частей помощников |
| `cache.models` | `["anthropic/"]` | Префиксы id моделей (с учётом регистра), чей провайдер принимает маркер `cache_control`. Запрос к модели вне списка отправляется без маркера |
| `cache.promptIncludesCached` | `true` | Включает ли `prompt_tokens` в ответе провайдера уже кэшированные и записанные в кэш токены. Задаётся однократно по реальному пробному запросу; калибровка и лимит на запрос в любом случае используют полный счёт |
| `hedge.roles` | `["analyzer", "reasoner"]` | Роли запросов, чьи вызовы хеджируются (две параллельные попытки, первая завершившаяся побеждает) |
| `hedge.afterMs` | `2500` | Миллисекунд до запуска второй попытки. `0` или меньше отключает хеджирование для всех ролей |
| `hedge.timeoutMs` | `8000` | Миллисекунд от начала первой попытки, по истечении которых обе отменяются, если ни одна не вернулась |
| `hedge.longTimeoutMs` | `20000` | Таймаут, используемый вместо `timeoutMs`, когда вызывающий помечает запрос `long: true` (классификатор маршрута делает это для большого списка каналов) |

`llm.provider` задаёт маршрутизацию провайдера OpenRouter по умолчанию для чат-запросов, например `{ "ignore": ["some-provider"] }` или `{ "order": ["anthropic"], "allow_fallbacks": true }`. `llm.providerByModel` добавляет переопределения по модели: ключ — это префикс id модели (для любой роли) или `<prefix>@<role>` (для одной роли), значение — объект маршрутизации OpenRouter, передаваемый как есть.

Порядок выбора провайдера для одного запроса: закреплённый маршрут конкретного вызова (для видео-описателя это `media.video.provider` при работе с прямым URL), затем самый длинный совпавший префикс среди ключей `providerByModel` для роли запроса, затем самый длинный совпавший префикс среди ключей без роли, затем `llm.provider` (для запросов изображений `image.provider`), затем ничего. Ключ с ролью всегда приоритетнее ключа без роли для той же модели. Имена ролей: `voice`, `analyzer`, `reasoner`, `extractor`, `vision`, `video`, `embedding`, `drawing`.

Пример: `"google/": { "only": ["google-vertex"], "allow_fallbacks": false }` направляет все модели Google через Vertex, а `"google/@video": { "only": ["google-ai-studio"], "allow_fallbacks": false }` отправляет видео-роль через AI Studio.

Если аккаунт OpenRouter ограничивает допустимых провайдеров, исключение единственного оставшегося даст ошибку "No endpoints found" на каждом запросе. После изменения настроек провайдера проверьте `/nep status`, чтобы убедиться, что каждая роль модели доступна; каждая роль следует своему маршруту из `llm.providerByModel`, поэтому показанный провайдер — тот, который выбран этим маршрутом.

При включённом `features.promptCache` системное сообщение маркируется для кэша промптов провайдера в запросах, чья роль есть в `llm.cache.roles` и чья модель начинается с префикса из `llm.cache.models`. Маркер ставится после оценки токенов, поэтому лимит 50k на запрос и калибровка не затрагиваются. `llm.cache.promptIncludesCached` сообщает движку, как провайдер считает кэшированные токены; задаётся однократно по реальному пробному запросу. В строке лога `llm: usage` появляется поле `cache`: `write`, `read`, `none` или `off`.

В строке лога `llm: usage` также содержатся `ms` (время запроса), `purpose` (краткая строка, для чего запрос, например `route-channel`, `recall-summary`, `address`), `origin` (например `replay` для запросов `tools/replay.mjs`), `hedged` (true, когда запрос хеджировался) и `attempt` (1 или 2 для хеджированных запросов, иначе отсутствует).

При настроенном `llm.hedge` запросы на ролях из его списка хеджируются: вторая попытка стартует через `llm.hedge.afterMs` после первой, и первая завершившаяся побеждает. Обе отменяются по `llm.hedge.timeoutMs` (или `longTimeoutMs` для запроса с `long: true`). Это добавляет один дополнительный запрос на каждый хеджированный вызов, не успевший до второй попытки; оба считаются в `llm.maxRequestsPerDay`.

## `roles`

Восемь ролей моделей. Каждая настраивается независимо через `roles.<name>` со своим значением по умолчанию, поэтому ни одна роль никогда не берёт модель другой роли. `roles.byPurpose` закрепляет конкретное назначение за собственной моделью независимо от роли.

**Переход со старых ключей.** Один релиз читает устаревшие ключи `llm.model`, `classifier.text`, `classifier.reason`, `classifier.media`, `classifier.video`, `classifier.embed`, `classifier.byPurpose`, `memory.model` и `image.model`. Старый `classifier.reason` со значением `null` (прежний откат к `classifier.text`) отображается в значение по умолчанию `roles.reasoner`. Перенесите значения вручную и удалите старые ключи.

## `embed`

| Ключ | По умолчанию | Описание |
|---|---|---|
| `dimensions` | `1024` | Размерность, запрашиваемая у модели эмбеддингов. Меньшее значение быстрее и дешевле, если модель поддерживает усечение |

Текст сообщений с именами авторов отправляется провайдеру эмбеддингов (OpenAI через OpenRouter). Локальное удаление убирает строки из индекса, но не удаляет копию текста у провайдера.

## `pace`

Утилиты `yt-dlp` и `ffmpeg` опциональны. Без них вложения в пределах лимитов работают (отправляются как есть). Длинные вложения и все ссылки на видеосайты откатываются к стоп-кадру или превью-картинке, а персонажу сообщается причина. Каждый запрос к видеомодели считается в `llm.maxRequestsPerDay` и в лимит токенов видео (`maxRequestTokens`).

Для YouTube-ссылок длительность определяется по цепочке: сначала yt-dlp, затем YouTube Data API (при наличии `YOUTUBE_API_KEY` в `.env`), затем разбор watch-страницы. Если все пробы провалились и `directUrlUnknownDuration` выключен (по умолчанию), ссылка сообщается как «не удалось загрузить». При включённом переключателе URL всё равно отправляется провайдеру, а в оценке токенов считается как `maxSeconds`. Ключ Data API бесплатен: включите YouTube Data API v3 в Google Cloud console и создайте ключ; бесплатная квота: 10 000 единиц/день, один запрос длительности стоит 1 единицу. При запуске бот проверяет `canaryUrl` и сообщает статус API key (например `youtube: API key — ok`). Закэшированный результат «превышение лимита длительности» запоминает длительность видео и повторяется при повышении лимита.

### `media.video.rewatch`

При включённом `damping` изменение, уводящее балл дальше от нуля, масштабируется как `(1 - |score| / 100) ^ dampingPower`, поэтому до краёв шкалы нужно долго идти; изменение обратно к нулю применяется в полную силу. Балл хранится дробным, а показывается целым; `/nep memory affinity` устанавливает его напрямую без демпфирования.

При установленном `decayPerDay` каждый сохранённый балл отношения (публичный и приватный) ежедневно дрейфует к нулю. При балле 100 с настройками по умолчанию дневная потеря составляет 4; при 64 около 1.6; при 30 около 0.36. Обход запускается при старте и ежечасно, применяя целые дни по метке `affinity.decayedAt` на профиле, поэтому простой наверстывается. Не работает в паузе и во время прогрева. Запись в историю отношений не создаётся.

| `kinds` | `{ "selfPicture": 3, "picture": 2, "meme": 1, "thought": 2, "people": 2, "news": 2, "facts": 1, "status": 3, "photoset": 1, "randomSet": 1 }` | Виды постов с весами. Вид с весом 0 не выбирается никогда. Планировщик видит веса и сколько последних постов использовали каждый вид. Перезагружается на лету, владелец может менять баланс в любой момент |
| `searchKinds` | `["news", "facts"]` | Виды, которые могут запустить веб-поиск. Планировщик пишет запрос только для этих видов |
| `pictureKinds` | `["selfPicture", "picture", "meme", "photoset", "randomSet"]` | Виды, которые всегда получают картинку, когда дневные лимиты на картинки позволяют, независимо от ответа планировщика. Остальные виды рисуют только если планировщик попросил |
| `setKinds` | `["photoset", "randomSet"]` | Виды, пост которых — набор картинок вместо одной. Держите их и в `pictureKinds`, чтобы они отбрасывались вместе с другими видами с картинкой, когда пост не может нести картинку |
| `set.pictures` | `[4, 6]` | Сколько картинок в наборе: промпт просит число между двумя значениями, бот генерирует не больше второго (первые теги `<draw>` ответа, остальные игнорируются) |
| `set.minPosted` | `2` | Набор, в котором сгенерировано меньше картинок, не публикуется вовсе, вместе с сообщениями. Генерация останавливается раньше, как только оставшиеся картинки уже не могут добрать это число. Уже сгенерированные картинки всё равно засчитываются в дневные лимиты на картинки |
| `set.seedSets` | `6` | Случайных комбинаций сидов в блоке `<seeds>` запроса составления для поста-набора (запрос планирования по-прежнему использует `seedSets`). `0` убирает блок |
| `set.maxMessageBytes` | `8000000` | Максимум байт картинок в одном сообщении Discord. Набор больше этого или из более чем 10 картинок разбивается на несколько сообщений |
| `planMaxOutputTokens` | `2000` | Максимум выходных токенов для запроса планирования |
| `planTimeoutMs` | `60000` | Таймаут запроса планирования (мс). Он же предел его хеджированного вызова, когда `llm.hedge.roles` включает `reasoner`, вместо `llm.hedge.timeoutMs` |

Окна по умолчанию (`windows`):

```json
[
  { "from": 7,  "to": 11, "posts": [0, 0] },
  { "from": 12, "to": 16, "posts": [0, 1] },
  { "from": 18, "to": 1,  "posts": [0, 2] },
  { "from": 1,  "to": 5,  "posts": [0, 1] }
]
```

Утро (7–11) выключено. День (12–16) разыгрывает 0 или 1 пост. Вечер (18–01 следующего дня) разыгрывает 0, 1 или 2. Ночь (01–05) разыгрывает 0 или 1. Все времена в `bot.timezone`. Окно, у которого `to` не больше `from`, переходит через полночь: `{ "from": 18, "to": 1 }` длится с 18:00 сегодня до 01:00 завтра.

## `private`

Настройки приватного чата (`features.privateMessages`). Все перезагружаются на лету. Шлюз проверяет их локально, без обращений к LLM.

| Ключ | По умолчанию | Описание |
|---|---|---|
| `minAffinity` | `5` | Минимальный публичный балл отношения для ответа на ЛС; владельцы обходят эту проверку |
| `maxPerUserPerDay` | `20` | Ходов ЛС на участника в день, дошедших до модели (с ответом или молчанием); при превышении публикуется уведомление раз в день |
| `maxPerOwnerPerDay` | `200` | Ходов ЛС в день для владельцев бота, дошедших до модели (с ответом или молчанием) |
| `purgeMaxMessages` | `5000` | Макс. сообщений в ЛС, которые `/nep memory private purge` сканирует (с конца) за один запуск |

При выключенном `features.relationships` публичные баллы остаются на 0, поэтому с `minAffinity` по умолчанию писать в ЛС смогут только владельцы.

## Модели

Движок использует восемь ролей моделей (`roles.*`). Каждая настраивается независимо: голос может работать на премиальной модели, а вспомогательные на дешёвых. Ни одна роль не берёт модель другой роли: ненастроенная роль сохраняет собственное значение по умолчанию.

### Голос

Наиболее мощная модель, которую позволяет бюджет. Качество ролеплея, стабильность характера и естественность разговора полностью зависят от неё. Более слабая модель выходит из роли, игнорирует подсказки контекста и звучит плоско. В двухэтапном режиме та же модель записывает и тексты памяти персонажа (назначения `reply`, `memory-voice`).

По умолчанию: `anthropic/claude-opus-4.6`. Бюджетный вариант: `anthropic/claude-sonnet-4.6`.

### Анализатор

Выбирает один из нескольких предложенных вариантов: address, room, merge, route-channel, participation-pick, rewatch, split, gif-pick. Самая дешёвая текстовая модель, способная надёжно отвечать «yes» или «no». По умолчанию: `openai/gpt-6.1-sol`.

### Рассуждающий

Планирует поиск и превращает источники в заметки: lookup, planner, recall-summary, search-summary, read-link, diary-plan. По умолчанию: `openai/gpt-6.1-sol`.

### Экстрактор

Превращает разговоры в сохранённую память: батчи анализатора, портреты, заметки каналов и сервера, прогрев, backfill. Рассуждает над длинными транскриптами и возвращает строгий JSON. В двухэтапном режиме (`features.memoryTwoStage`) эта модель выполняет этап A (нейтральные решения). По умолчанию: `openai/gpt-6.1-sol`.

### Эмбеддинги

Модель эмбеддингов, для поиска по смыслу. По умолчанию: `openai/text-embedding-3-large` с `embed.dimensions` 1024. Запросы идут через тот же транспорт, повторы и дневной лимит, что и чат-запросы. Карточка `/nep status` проверяет запросом на один вход; без клиента эмбеддингов строка сообщает, что проверка не проводилась.

### Картинки

Любая дешёвая модель со зрением. Пишет однострочные описания, поэтому мощность рассуждений почти не важна.

По умолчанию: `google/gemini-3.8-flash`. Самая дешёвая альтернатива: `google/gemini-2.5-flash-lite`.

### Видео

Здесь подходят только модели, принимающие ОДНОВРЕМЕННО видео и аудио на входе через OpenRouter. Модели, принимающие кадры, но не аудио (Qwen VL, GLM, Seed, Gemma), не слышат речь и упускают большую часть смысла.

`google/gemini-flash-latest` это плавающий псевдоним, цена которого может измениться без предупреждения. Пакетные (`:batch`) варианты асинхронны и непригодны для ответа в реальном времени. Путь с прямым URL (YouTube в пределах лимита длительности, отправляется как публичный URL с `media.video.provider`) требует Google AI Studio в качестве провайдера.

### Генерация картинок

Генерирует картинки через OpenRouter Images API (`POST /api/v1/images`). Поддерживаются только два семейства: `openai/*` и `google/*`. Неподдерживаемое семейство отклоняется до отправки запроса или подсчёта.

**Модели OpenAI.** Учитывают `image.openai.quality`, `image.openai.background`, `image.openai.moderation`, `image.aspectRatio`, `image.outputFormat` и `input_references`.

| Модель | Примечания |
|---|---|
| `openai/gpt-image-2.5-flare` (default) | Быстрый тир |
| `openai/gpt-image-2.5-sunburst` | Тир высокой точности |
| `openai/gpt-image-2` | |
| `openai/gpt-image-1` | |
| `openai/gpt-image-1-mini` | |

**Модели Google.** Учитывают `image.google.resolution`, `image.aspectRatio`, `image.outputFormat` и `input_references`. `image.aspectRatio` со значением `auto` не отправляется в запросе Google.

| Модель | Примечания |
|---|---|
| `google/gemini-3.1-flash-image` | Nano Banana 2 |
| `google/gemini-3-pro-image-preview` | |
| `google/gemini-2.5-flash-image` | Без параметра разрешения |

Тарификация за выходные токены, а не за картинку; `usage.cost` от провайдера показывается в `/nep draw` и логируется. Запрос, отклонённый движком до отправки (дневной или пользовательский лимит, неподдерживаемое семейство моделей), ничего не стоит; генерация, отклонённая провайдером, как правило, не тарифицируется; таймаут или неудачная загрузка картинки, которая уже была сгенерирована, могут быть тарифицированы.
