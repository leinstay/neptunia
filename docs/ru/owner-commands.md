# Команды

Одна слэш-команда `/nep` с 19 корневыми записями. Все ответы эфемерные (видит только вызвавший). Каналы, роли и пользователи выбираются из стандартных пикеров Discord. Несколько опций автодополняются: `set`/`unset` автодополняют `path`, `access grant`/`access revoke` автодополняют `command`, `model set` автодополняет `id` (используемые модели), `route set`/`route remove` автодополняют `model`, `memory restore` автодополняет `id` (новейшие записи архива).

## Доступ

`/nep` видна каждому участнику с самого начала. Доступ проверяется по операциям в момент выполнения команды, а не через видимость в Discord. Каждая команда выполняет одну именованную операцию. Чтение и запись разделены: `/nep memory show` выполняет `memory.profile.read`, `/nep memory affinity <user>` выполняет `memory.affinity.read`, а `/nep memory affinity <user> <score>` выполняет `memory.affinity.set`.

Владельцы (`bot.owners`) всегда могут выполнять всё. Остальным нужно разрешение на конкретную операцию. `/nep access grant <operation> [role] [user]` открывает одну операцию (например `memory.profile.read`) всем (без роли/пользователя), роли или пользователю. Имя группы (например `memory`) или `*` принимаются, но разрешение записывается как отдельные операции чтения, существующие в этот момент: запись оно не открывает, и операция, добавленная позже, остаётся закрытой до явного разрешения по имени. `/nep access revoke` убирает цель из одной операции или из всех записанных операций в группе или `*`. `/nep access list` показывает каждую операцию, кому она доступна и откуда пришло разрешение (когда оно было частью расширения группы или `*`). Без разрешения участник получает эфемерный ответ "Not allowed".

Операции только для владельцев (`access.*`, `skill.*`, `diary.*`, `memory.private.*`, `memory.journal.read`, `memory.snapshot`, `memory.forget`, `memory.wipe`, `memory.archive.read`, `memory.restore`) не открываются никаким разрешением, `*` включительно.

**Миграция со старых ключей команд.** При первом запуске после деплоя с операционной системой доступа все записанные разрешения конвертируются: старый ключ команды становится операцией, которую он выполнял; старая группа или `*` раскрывается в операции чтения, которые она покрывала; операции только для владельцев удаляются. Запись `system` `access-migrated` в журнале перечисляет, что каждое старое разрешение теперь покрывает. После миграции: `/nep access revoke * everyone`, затем `/nep access grant memory.profile.read everyone`, и по имени выдайте другие нужные операции (проверьте `/nep access list`).

## Статус

`/nep status` показывает одну карточку с самыми важными для быстрой проверки полями: состояние бота (работает или на паузе с какого момента, плюс строка хранилища), шлюз, долгие задачи (бэкфиллы, разгрузка архива), модели по группам (voice, analyzer, reasoner, extractor, media = vision + video, embedding, drawing; по строке на роль: роль, модель, провайдер, задержка; `roles.byPurpose` под своей ролью), дневные лимиты, покрытие памяти по типу (record, index, archive, профили, заметки сервера, каналы, недавние строки, participation: количество, диапазон, процент), скорость за последние 24 часа (медиана, среднее и количество для ответа, recall, планировщика, батча анализатора, flush эмбеддингов; семплы в `data/metrics.json`) и аптайм. Каждая роль показывает свою собственную модель (никогда модель другой роли); ни одна роль не использует модель другой. Роль эмбеддингов проверяется одним запросом на один вход (текст из `status.probe`); без клиента эмбеддингов строка сообщает, что проверка не проводилась. `/nep status detail` добавляет длинную текстовую форму под карточкой: калибровку моделей, прогресс прогрева, каждый загруженный промпт с источником и голосовую очередь. Участник с разрешением `status.show` видит карточку без полей памяти и скорости и никогда не видит длинную форму.

## Команды навыков

`/nep skill allow` и `/nep skill deny` переключают отдельные навыки для персонажа. Два уровня: разрешён или нет. Согласие в чате никогда не открывает навык: только команда владельца, аутентифицированная Discord, меняет доступ. Персонаж может попросить навык словами, а навык `access.request` оставляет запись для владельца, но решение принимает владелец через команду.

`/nep skill list` показывает каждый зарегистрированный навык с его текущим состоянием: разрешён (кем и когда), унаследован (только текущий разговор) или не разрешён. Когда `features.skills` выключен, список сообщает об этом. Когда `skills.safeMode` включён, список сообщает об этом.

**Унаследован (только текущий разговор)** означает, что обычные теги ответа персонажа (`<msg>`, `<react>`, `<draw>`) считаются навыками `message.send`, `message.react.add` и `draw` в текущем разговоре без записи разрешения. Так персонаж продолжает говорить: его ответ является набором вызовов навыков, которые проходят шлюз, потому что направлены в разговор текущего хода. Запись разрешения открывает навык и для других разговоров.

Все три операции (`skill.allow`, `skill.deny`, `skill.list`) доступны только владельцу. Каждое изменение доступа записывается в журнал как запись `system` `skill-access`.

## Команды памяти

`/nep memory show` показывает профиль участника: компактную сводку или конкретную секцию (character, style, relationship, affinity, aliases, interests, details, episodes или необработанный JSON). `/nep memory channel` показывает заметки канала или таблицу всех каналов. `/nep memory server` показывает серверные паттерны, стартеры, шутки и факты о себе.

`/nep memory forget` удаляет публичный профиль, приватный файл ЛС, элементы голосовой очереди, историю версий, записи в журнале и архиве. Перед удалением всё копируется в каталог хранилища (`memory.vaultDir`, по умолчанию `data/vault/`), а id участника записывается в `data/guilds/<id>/forgotten.json`. Движок никогда не читает хранилище обратно; для восстановления скопируйте файлы вручную и удалите запись из `forgotten.json`. `/nep memory wipe` делает то же для всей памяти сервера: копирует всё из каталога гильдии в хранилище, затем удаляет профили, приватные файлы, каналы, привычки, лор, журнал, реестр, архив, голосовую очередь, версии, историю дневника и трассировку recall.

`/nep memory journal` показывает записи журнала персонажа за UTC-день, с фильтрацией по виду (turn, action, memory, system). `/nep memory archive` показывает архивные элементы, с фильтрацией по участнику или виду. `/nep memory restore` возвращает архивный элемент в горячую память (`id` автодополняется из новейших записей). `/nep memory snapshot` копирует `data/` в каталог с временной меткой для инструментов измерения.

`/nep memory private show` показывает приватную память ЛС участника. `/nep memory private forget` удаляет только приватный файл; публичный профиль остаётся. `/nep memory private purge` удаляет приватный файл и также массово удаляет сообщения бота в ЛС с участником (до `private.purgeMaxMessages`).

## Команды участников

`/nep pings` единственная команда, доступная каждому участнику без разрешения `bot.access`. `features.memberCommands: false` ограничивает доступ владельцами.

| Команда | Описание |
|---|---|
| `/nep pings [mode]` | Показать или изменить, уведомляет ли вас персонаж своими сообщениями. Без `mode`: текущая настройка. `on` / `off`: установить предпочтение. Когда выключено, ответ на ваше сообщение не содержит пинга, а @упоминание вас в тексте персонажа отображается, но не уведомляет. Текст персонажа не меняется. Эфемерный ответ: `Pings: on` или `Pings: off`. Хранится по серверу, переживает перезапуски, удаляется только по `/nep memory wipe` |
