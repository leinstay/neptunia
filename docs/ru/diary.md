# Дневник

Персонаж сам пишет в один канал, в случайное время, без чьей-либо просьбы. Посты выглядят как личная лента: рисунки сцен из мира персонажа, мемы, размышления, пересказы новостей, любопытные факты, настроение одной строкой. Перед каждым постом персонаж просматривает свою историю и выбирает то, чего ещё не было. Владелец указывает канал и настраивает расписание и виды через конфигурацию.

## Настройка

1. Создайте канал на сервере. Боту нужны права View Channel, Send Messages, Read Message History и Attach Files.
2. Выполните `/nep diary set <channel>`. Команда проверяет права, записывает `diary.channelId` в `config.local.json` и заполняет историю из прошлых постов персонажа (если она пуста).
3. Дневник начнёт постить на следующем тике (каждые 30 секунд). Первый пост может появиться через несколько минут, в зависимости от ближайшего слота.

`/nep diary show` показывает сегодняшний план: канал, слоты в `bot.timezone`, сколько постов и картинок использовано сегодня, размер истории.

`/nep diary off` убирает канал. Файл истории остаётся, так что повторное включение сохраняет память о прошлых постах.

`/nep diary post [kind] [topic]` принудительно публикует один пост прямо сейчас, вне плана. Если идёт ход, команда ждёт его завершения до `diary.forceWaitMs` (120000 мс, две минуты); если ожидание истекает, отвечает `busy`. Дневные лимиты действуют. Необязательный ключ вида (например `selfPicture`, `thought`) переопределяет выбор планировщика; неизвестный вид отклоняется со списком доступных. Необязательная тема в свободной форме направляет пост на указанный предмет.

## Окна

Времена постов разыгрываются из окон: каждое окно описывает диапазон часов в `bot.timezone` с `[min, max]` числом постов. Окно, у которого `to` не больше `from`, переходит через полночь. Для каждого окна планировщик разыгрывает целое число между `min` и `max` и размещает столько слотов в случайные моменты внутри окна. Слоты, расположенные ближе `diary.minGapMinutes` (90) друг к другу, отбрасываются; когда их остаётся больше `diary.maxPerDay` (3), лишние отбрасываются случайным образом.

Четыре окна по умолчанию (все в `bot.timezone`):

| Окно | Часы | Посты |
|---|---|---|
| Утро | 07–11 | `[0, 0]` (выключено) |
| День | 12–16 | `[0, 1]` |
| Вечер | 18–01 | `[0, 2]` |
| Ночь | 01–05 | `[0, 1]` |

С вероятностью `diary.quietDayChance` (0.3) весь день остаётся без слотов. План создаётся раз в локальный день (дата в `bot.timezone`) и сохраняется в `data/state.json`. Новый день создаёт новый план; перезапуск сохраняет текущий.

Дни не независимы: дневник «голодает». У каждого окна есть счётчик голода; `/nep diary show` выводит его строкой `hunger: 0/1/2 (quiet streak 1)`, по одному числу на окно в порядке конфига, а журнал пишет его в каждой записи `diary: plan`. Тихий день добавляет каждому окну одно очко голода, а каждый следующий тихий день подряд умножает шанс тихого дня на `diary.quietCarry` (0.25): по умолчанию второй тихий день подряд выпадает с шансом 7,5% вместо 30%. Окно, чей запланированный пост вышел, обнуляется; окно, в котором ничего не вышло (слотов не было, слот пропущен, пока бот был выключен, или отклонён), получает очко. Если голодному окну выпало ноль постов, оно перебрасывает число ещё раз за каждое очко голода, и каждый дополнительный бросок перевыбирает число с шансом 1 минус `diary.hungerBoost` (0.5). Внутри одного дня каждое пустое окно добавляет очко и всем окнам после него, так что молчаливое дневное окно делает вечерний пост вероятнее. Окно `[0, 0]` никогда не постит и не голодает. Ручной `/nep diary post` не считается: окно насыщают только запланированные посты.

Слот, пропущенный более чем на `diary.slotGraceMinutes` (30) минут (бот был выключен), отбрасывается. Слот, заблокированный занятым вниманием, повторяется на следующем тике в пределах грейса.

## Стоимость одного поста

Каждый пост дневника состоит из двух запросов к модели:

1. Запрос планирования на модели `classifier.text`: выбор вида, краткого описания, решение о поиске и картинке.
2. Запрос составления на основной модели (`llm.model`) с карточкой персонажа и всеми блоками памяти.

Когда план просит веб-поиск (только для `diary.searchKinds`, по умолчанию `news` и `facts`), поиск Brave добавляет третий запрос (конденсер на `classifier.text`). Поиск учитывается в `web.maxPerDay`.

Когда пост включает картинку, модель изображений генерирует её по своей цене. Картинки дневника учитываются и в `image.maxPerDay`, и в `diary.maxPicturesPerDay` (2).

Каждый запрос модели учитывается в `llm.maxRequestsPerDay`. При настройках по умолчанию (1–3 поста в день, 2–3 запроса на пост, до 2 картинок) день обходится примерно в 3–9 запросов плюс генерация картинок.

## Виды и сиды

`diary.kinds` сопоставляет каждый ключ вида с весом. Планировщик видит веса и сколько из последних `diary.historyPosts` постов использовали каждый вид, поэтому предпочитает виды, которые были реже. Вид с весом 0 не выбирается никогда. Ключи и значения по умолчанию:

| Вид | Вес | Что это |
|---|---|---|
| `selfPicture` | 3 | Персонаж в сцене, каждый раз новая обстановка |
| `picture` | 2 | Рисунок без персонажа: место, животное, что-то о человеке с сервера |
| `meme` | 1 | Мем, нарисованный персонажем |
| `thought` | 2 | Размышление, рецензия, мнение |
| `people` | 2 | Пост об одном человеке с сервера: что он недавно делал или говорил, что персонаж о нём думает |
| `news` | 2 | Что-то найденное в интернете, что интересно людям сервера |
| `facts` | 1 | Любопытный факт, запись айсберга, конспирология как конспирология |
| `status` | 3 | Одна короткая строка: настроение, план, скука |

`diary.searchKinds` (по умолчанию `["news", "facts"]`) определяет, какие виды могут запустить поиск. `diary.pictureKinds` (по умолчанию `["selfPicture", "picture", "meme"]`) определяет виды, которые всегда получают картинку, когда дневные лимиты позволяют, независимо от ответа планировщика. Остальные виды рисуют только если планировщик попросил. Когда пост не может содержать картинку (дневные лимиты на картинки исчерпаны, рисование выключено, нет модели изображений или у бота нет права Attach Files в канале дневника), планировщик видит только текстовые виды. Принудительный вид с картинкой через `/nep diary post` отклоняется до любого запроса: ответ указывает лимит и его счётчики, когда причиной был лимит, или говорит `pictures` в остальных случаях.

`prompts/diary-seeds.md` содержит случайные сиды, сгруппированные по заголовкам `# family` (place, setting, detail, activity, subject, twist). Код выбирает одну строку из каждой семьи и составляет `diary.seedSets` (2) комбинаций, которые получает планировщик в блоке `<seeds>`. Комбинаций почти бесконечное количество; планировщик строит из них то, чего нет в истории дневника, или игнорирует их, если жизнь сервера подсказывает лучшую идею.

Для настройки сидов скопируйте `prompts/diary-seeds.md` в `prompts.local/diary-seeds.md` и отредактируйте строки. Каждая строка под заголовком является одним сидом; пустые строки игнорируются.

## Мир персонажа

`prompts/world.md` описывает виртуальный мир персонажа: места и привычки за пределами чата. Отслеживаемый файл содержит нейтральный пример. Чтобы написать свой, создайте `prompts.local/world.md` (он полностью заменяет отслеживаемый, как `appearance.md`).

Блок `<world>` появляется только в двух запросах дневника (планирование и составление) и только при `diary.world === true` (по умолчанию `false`). Включается через `/nep set diary.world true`. Без него персонаж не имеет постоянного дома и не заявляет о нём.

Файл мира никогда не появляется в обычном ходе чата. Текст сцены, который персонаж пишет в теге `<draw>`, несёт всё, что нужно видеть модели изображений.
