---

Neptunia это локально работающий Discord-бот, который отыгрывает одного настраиваемого с помощью LLM персонажа и ведёт себя как обычный участник чата. Работает на Node.js 20+ с единственной зависимостью (discord.js) и любым OpenRouter-совместимым эндпоинтом. Карточка персонажа пишется без правки кода, промпты и конфигурация перезагружаются на лету. Есть память по каждому участнику с отношением и эпизодами, серверный лорбук, зрение для прикреплённых картинок, однострочные описания медиа от вспомогательной модели, рисование по запросу через модель генерации изображений, приватный чат в личных сообщениях Discord с отдельным слоем памяти, слэш-команды владельца для настройки на ходу и режим сухого прогона. В комплекте рабочий пример персонажа; для другого напишите свою карточку.

Персонаж отвечает на упоминания, ответы и триггеры по имени, иногда игнорируя их. Вклинивается в разговоры в случайные моменты и заводит темы в тихих каналах. Запоминает людей, ведёт отношение от -100 до 100 и учитывает его в ответах. Балл в чате не виден. Конфигурация и промпты перезагружаются на лету; команды владельца настраивают бота прямо из Discord.

Каждый экземпляр обслуживает один сервер, один аккаунт бота, одну личность. Для второго сервера или персонажа запустите вторую копию со своими `.env`, `config.local.json`, `prompts.local/` и `data/`. Discord помечает бот-аккаунты значком APP; движок этого не скрывает.

## Быстрый старт

Создайте приложение Discord на [discord.com/developers](https://discord.com/developers/applications). Включите привилегированный интент **Message Content** на странице Bot. В ссылке приглашения нужны оба scope (`scope=bot%20applications.commands`) и `permissions=101440` (просмотр каналов, отправка сообщений, чтение истории, добавление реакций, прикрепление файлов). Если слэш-команды не появились после добавления бота, причина будет в логе; достаточно снова открыть ссылку приглашения и пройти её заново, удалять бота не нужно.

Получите API-ключ на [OpenRouter](https://openrouter.ai/keys) (или на любом совместимом эндпоинте).

```bash
git clone https://github.com/leinstay/neptunia-bot.git
cd neptunia-bot && npm install
cp .env.example .env
```

Отредактируйте `.env`, указав токен Discord и API-ключ. Создайте `config.local.json` со своим Discord user ID:

```json
{
  "bot": {
    "owners": ["YOUR_DISCORD_USER_ID"]
  }
}
```

```bash
npm start
```

Когда `bot.guildId` пуст и бот находится ровно на одном сервере, он привязывается к нему автоматически. Если бот на нескольких серверах, он откажется запускаться. Укажите `bot.guildId` в `config.local.json`.

## Возможности и изменения

**13.10.2026**  
Каждое услышанное и каждое отправленное сообщение записывается в постоянный реестр на диске. Когда горячая память заполняется и эпизод, интерес или деталь вытесняются, элемент попадает в файл архива до удаления. При поиске по серверу движок читает архив и несколько последних дней реестра наряду с результатами поиска Discord, чтобы персонаж мог найти даже то, что давно покинуло профили. Факты, которые меняются со временем (текущая игра, прозвище, шутка про «сегодня день рождения»), несут даты: когда факт был верен, когда перестал быть верным, и что его заменило. Два противоречивых открытых утверждения показываются вместе, а не одно молча затирает другое. `/nep memory forget` копирует всё, что собирается удалить, в каталог хранилища внутри `data/` и записывает удаление в реестр (`forgotten.json`), чтобы ничто не было потеряно безвозвратно.

Персонаж ведёт журнал: для каждого хода одна запись с тем, что из чата попало в запрос, скрытым рассуждением персонажа, тем, что он написал, и расходом токенов, по дням в `data/`. Полный запрос к модели и необработанный ответ тоже сохраняются на несколько дней (`journal.keepRequests`), чтобы можно было разобрать неудачный ответ после факта. `/nep status` показывает одну карточку с состоянием бота, подключением, моделями, дневными лимитами и счётчиками памяти; участники с разрешением видят карточку без полей памяти. Инструмент бэкфилла (`tools/backfill.mjs`) заполняет прошлое персонажа из старых сообщений: читает историю в реестр, извлекает эпизоды и уроки, и по желанию отправляет сильнейшие через голосовую модель для чувства словами персонажа. Результаты попадают в архив, а не в горячую память, и всплывают через recall.

Каждая подкоманда `/nep` выполняет именованную операцию с раздельными правами на чтение и запись. Владельцы всегда могут выполнять всё; для остальных каждая операция разрешается по имени, а разрешение на группу открывает только операции чтения, существующие на тот момент. На свежем сервере участникам доступен только `/nep pings`, пока владелец не выдаст остальное. Операции только для владельцев (разрешения доступа, forget, wipe, журнал, архив, снапшоты и приватная память) не открываются никаким разрешением. Ментор (`features.mentor`) удалён. `/nep ping` и `/nep reload` убраны: проверка подключения теперь в `/nep status`, а промпты перезагружаются автоматически.

Ведёт дневник: один канал, в который пишет сама, без чьей-либо просьбы. Посты появляются в случайное время в течение дня по настраиваемым окнам, с тихими днями вперемешку. Если её позвали в канале, где у неё нет права писать, отвечает в основном канале со ссылкой на то сообщение. Может сама прокомментировать в основном канале то, что прочитала там, где писать не может. Когда её спрашивают о человеке, вспоминает случаи, связанные с ним. Ищет по старым сообщениям сервера так же, как в интернете: на вопросы вроде «что мы делали на Новый год» или «кто такой …» находит нужную переписку и отвечает по ней.

## Слои промптов

Промпты загружаются из двух директорий:

- `prompts/`: отслеживаемые дефолты движка с рабочим примером персонажа.
- `prompts.local/`: ваш персонаж (в gitignore). Файл здесь заменяет одноимённый файл в `prompts/`. `labels.json` объединяется глубоким слиянием, поэтому достаточно переопределить только нужные ключи.

Оба каталога перезагружаются на лету.

Переписать нужно только один файл: `character-card.md`. Скопируйте его в `prompts.local/` и опишите своего персонажа. Всё остальное работает из коробки; при необходимости переопределяйте отдельные файлы.

Файлы промптов, плейсхолдеры, метки, контекстные блоки и теги вывода описаны в [`prompt-contract.md`](prompt-contract.md).

## Конфигурация

`config.json` содержит все настройки с дефолтами. `config.local.json` (в gitignore) объединяется глубоким слиянием поверх него. Оба перезагружаются на лету. Полный справочник по всем ключам: [`configuration.md`](configuration.md).

## Прогрев

При первом запуске, если `warmup.enabled` включён и профилей ещё нет, движок запускает прогрев: строит память о людях, каналах и сервере из выборки недавних сообщений. Расход токенов ограничен `warmup.maxTokens`. Персонаж молчит, пока идёт прогрев. Подробнее: [`warmup.md`](warmup.md).

## Сухой прогон

При `features.dryRun: true` бот выполняет весь пайплайн (память, триггеры, вызовы LLM), но не отправляет ни сообщений, ни реакций. Вывод попадает в лог (`dry-run: would send` / `dry-run: would react`). Укажите в `bot.dryRunChannelId` приватный канал, чтобы получить читаемое зеркало; всё, что публикуется в этом канале, бот игнорирует. Слэш-команды работают в любом канале, включая зеркало, потому что это не сообщения.

Первый запуск на новом сервере: включите `features.dryRun`, следите за зеркалом или `journalctl -u neptunia-bot -f`, настраивайте на лету, затем `/nep set features.dryRun false`.

## Команды

Одна слэш-команда Discord: `/nep` (имя задаётся в `bot.commandName`), зарегистрированная как серверная команда. Все ответы эфемерные; их видит только вызвавший, в любом канале.

18 корневых записей:

- `status` показывает карточку с состоянием бота, подключением, моделями, лимитами и счётчиками памяти
- `set` / `unset` переопределяют или удаляют значение конфигурации в `config.local.json`
- `pause` / `resume` останавливают активность и сбрасывают память для ручной правки `data/`
- `draw` рисует картинку в текущем канале
- `pings` позволяет участнику отключить уведомления от персонажа
- `talk` заставляет персонажа вклиниться или начать тему в канале
- `media` управляет рейтингом эмодзи и библиотекой GIF (status, rescan, recache)
- `model` показывает или устанавливает модель для каждой роли
- `route` управляет маршрутизацией провайдеров по префиксу модели и роли
- `rule` добавляет, показывает или удаляет правки в `prompts.local/rules.md`
- `access` выдаёт или отзывает операции для ролей и пользователей
- `diary` указывает, показывает или отключает дневник и публикует запись
- `alias` добавляет или удаляет псевдоним участника
- `learning` добавляет или удаляет урок
- `lore` добавляет, показывает или удаляет записи лорбука
- `memory` покрывает профили, каналы, серверные заметки, отношение, обновление портрета, forget, wipe, журнал, архив, восстановление, снапшоты и приватную память

Владельцы (`bot.owners`) могут всё. Остальным нужно разрешение на конкретную операцию; чтение и запись разделены, и разрешение на группу или `*` открывает только операции чтения, существующие на тот момент. На свежем сервере участникам доступен `pings` и ничего больше, пока владелец не выдаст разрешения. Операции только для владельцев (разрешения доступа, forget, wipe, журнал, архив, снапшоты и приватная память) не открываются никаким разрешением. Полная таблица и модель доступа: [`owner-commands.md`](owner-commands.md).

## Сообщения и память

Персонаж отвечает на упоминания, ответы и триггеры по имени, иногда игнорируя их. Вклинивается в разговоры в случайные моменты, заводит темы в тихих каналах и может подхватить вопрос, заданный всей комнате. После ответа следит за продолжением через классификатор. Пишет один ответ за раз на весь сервер; пинги в других каналах откладываются и обрабатываются по очереди, любое количество на канал и автора, до `mention.maxPending` (по умолчанию 6). Если сообщение содержит несколько отдельных просьб, каждая получает ответ в отдельном ходе. Если кто-то пишет ещё одно сообщение о том, что уже ждёт в очереди, оно объединяется с ожидающим элементом, а не ставится в очередь отдельно. Когда в разговоре упоминают другой канал, классификатор определяет канал, чтобы персонаж мог его прочитать.

Отдельный анализатор памяти запускается, когда накопится достаточно сообщений. Он строит профили участников с интересами, деталями, псевдонимами, эпизодами и отношением, серверные привычки и шутки, лорбук событий и историй, а также список того, чему люди научили персонажа напрямую (слова, факты, просьбы). Профили обновляются инкрементально; сохранённые факты не пересказываются. Персонаж также запоминает, как люди называют друг друга, и узнаёт участника по имени или псевдониму. Уроки хранятся на уровне сервера (`memory.maxLearned` показывается, `memory.maxLearnedStored` хранится на диске, `memory.learnedChars` на элемент) и всегда присутствуют в промпте.

Память хранится в слоях. Горячая память: профили, заметки и списки, которые персонаж несёт в каждом запросе. Реестр: постоянный append-only лог в `data/`, куда записывается каждое услышанное и отправленное сообщение до анализа. Архив: всё, что покидает горячую память (вытесненные эпизоды, интересы, детали, уроки, дневниковые записи), копируется в файл архива до удаления. Когда персонажа спрашивают о старых событиях, recall-поиск читает архив и последние дни реестра наряду с поиском Discord, и элементы, покинувшие горячую память, всё ещё можно найти. `/nep memory forget` копирует всё, что собирается удалить, в каталог хранилища (`memory.vaultDir`, по умолчанию `data/vault/`) и записывает id участника в реестр (`forgotten.json`). Движок никогда не читает хранилище обратно; для восстановления скопируйте файлы вручную. `/nep memory wipe` делает то же для всего сервера.

Подробнее: [`messages-and-memory.md`](messages-and-memory.md).

## Медиа

Персонаж может видеть прикреплённые картинки, смотреть короткие видеоклипы, читать страницы по ссылкам, искать в интернете и по истории сообщений сервера факты, которых у него нет, рисовать картинки по запросу через модель генерации изображений и отправлять GIF из библиотеки, собранной из того, чем делятся участники. У каждой возможности есть отдельный переключатель, выключенный или ограниченный по умолчанию, и собственный дневной лимит. Блок `<senses>` в каждом запросе сообщает персонажу, что включено; он никогда не утверждает, что воспринял что-то сверх указанного. Картинки, видео, чтение ссылок, поиск, рисование, инструменты, стоимость и приватность описаны в [`media.md`](media.md).

## Приватный чат

`features.privateMessages` (выключен по умолчанию) позволяет участникам сервера писать персонажу в личные сообщения Discord. Персонаж остаётся тем же с той же публичной памятью; сказанное в ЛС запоминается в приватном слое для каждого участника, невидимом другим разговорам. Для ЛС требуется членство на том же сервере и никаких дополнительных прав сверх тех, что даёт ссылка приглашения. Шлюз, приватный слой памяти и команды владельца описаны в [`messages-and-memory.md`](messages-and-memory.md#приватный-слой).

## Стоимость

Каждый ход стоит один запрос к LLM; обновление памяти добавляет второй. Классификатор разделения и классификатор объединения могут добавить по одному запросу на модели `classifier.text`, когда срабатывают их условия. Стоимость зависит от модели и эндпоинта; `llm.model` и `llm.baseUrl` принимают любые совместимые значения. Дневной лимит (`llm.maxRequestsPerDay`) предотвращает перерасход. Описания видео добавляют по запросу за клип к отдельной, более дешёвой модели (`media.video.maxPerDay` ограничивает дневное число); `yt-dlp` и `ffmpeg` работают локально и не стоят ничего, кроме трафика. Чтение ссылок и веб-поиск (`features.webLookup`, выключен по умолчанию) добавляют запросы к текстовому классификатору, ограничены `web.maxPerDay`; для веб-поиска дополнительно нужен ключ Brave Search API (бесплатный лимит: 2 000 запросов в месяц). Поиск по истории сообщений сервера (`features.recall`, включён по умолчанию) использует встроенный поиск Discord и добавляет только запросы к классификатору и помощнику по сводке. Генерация картинок (`features.imageGeneration`, выключена по умолчанию) тарифицируется за выходные токены через `image.model`; `image.maxPerDay` ограничивает дневное число отдельно от запросов чата. Приватный чат (`features.privateMessages`, выключен по умолчанию) использует те же LLM и лимиты; каждый ответ в ЛС — один запрос, каждый приватный батч анализатора — ещё один. При включённом `features.webLookup` бот делает исходящие HTTP-запросы к страницам и к Brave Search API; приватные адреса отклоняются.

`data/` хранит профили участников, баллы отношений, наблюдения по каналам, серверные паттерны, кэш описаний медиа и веб-выдержки. Всё остаётся на вашей машине, в gitignore, и попадает в LLM только как контекст. Анализатору дана инструкция не хранить конфиденциальные данные. `/nep memory forget` полностью удаляет профиль.

Предупредите участников сервера. Они должны знать, что их сообщения обрабатываются LLM и что бот ведёт заметки.

## Сервис

Пример юнита systemd: `deploy/neptunia-bot.service`. Настройте `WorkingDirectory` и `User`, затем установите:

```bash
sudo cp deploy/neptunia-bot.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now neptunia-bot
```

Приватный слой живёт рядом с кодом: `.env`, `config.local.json`, `prompts.local/`, `data/`. Обновление:

```bash
git pull && sudo systemctl restart neptunia-bot
```

При перезапуске ничего не теряется; всё состояние на диске. Перезапуск нужен только после изменений кода в `src/`. Правки промптов и конфигурации применяются на лету.

Память живёт в процессе и пишется в `data/`; редактировать эти файлы при работающем боте опасно, потому что следующая запись затрёт правку. Чтобы править память вручную: `/nep pause`, правка файлов, `/nep resume`. Пауза останавливает всю активность, сбрасывает память на диск и выгружает её; запущенный прогрев приостанавливается после текущего запроса. Состояние сохраняется: после перезапуска бот остаётся на паузе, и прогрев не стартует автоматически до возобновления. `/nep resume` проверяет каждый JSON-файл в `data/` и отказывает, если хоть один не разбирается, перечисляя сломанные; иначе перезагружает память и продолжает, включая прогрев с места остановки. Команды чтения и конфигурации работают на паузе; команды записи памяти отклоняются. `/nep status` показывает состояние паузы.

## Участие

Приветствуются issues и pull requests; сначала прочитайте `CONTRIBUTING.md`. Целевая ветка `main`, одно изменение на pull request, тесты проходят (`npm test`), всё на английском. Контракт между файлами промптов и кодом описан в `docs/ru/prompt-contract.md`. Изменение одной стороны требует изменения другой в том же pull request. Движок остаётся нейтральным к персонажу; поведение конкретного персонажа живёт в `prompts.local/` конкретного развёртывания. Об уязвимостях сообщайте по `SECURITY.md`, а не в публичных issues.

## Тесты

```bash
npm test
```

Запускается через `node --test`. Ни сеть, ни подключение к Discord не нужны. Та же команда выполняется в CI при каждом pull request.
