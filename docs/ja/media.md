# メディア

ペルソナが何を見て、聞いて、読めるか、そしてそれを可能にするヘルパーについて。

トランスクリプトの行にはメディアマーカーが括弧で表示されます: 画像、GIF、動画、スティッカー、カスタム絵文字、ボイスメッセージ、音声ファイル、リンク、テキストファイルのプレビュー、転送されたメッセージ。ペルソナが実際に何を知覚するかは以下の機能に依存します。ユーザーメッセージの `<senses>` ブロックが、現在の設定で何が有効で何が無効かをペルソナに伝えます。ペルソナはこのブロックを信頼し、そこに記載されている以上のものを見た、聞いた、開いたと主張しません。

## 画像

`features.vision` は呼び出しメッセージ、リプライ先のメッセージ、チャンネル内の最新の画像を、Discord のメディアプロキシ経由でダウンスケールして LLM リクエストに画像として添付します。ボットはすべての画像を自分でダウンロードし、データとしてインライン送信します。Discord がモデルプロバイダーからのダウンロードを拒否するためです。`context.vision.maxBytes` を超える画像や `context.vision.fetchTimeoutMs` より遅い画像はスキップされます。ペルソナはこれらを直接見ます。ヘルパーは不要です。

`features.imageRelook` がオン（デフォルト）で、ペルソナに画像についての質問や具体的な主張が向けられた場合、再視聴分類器が動画と共に最近の画像も提供し、ビジョンモデルがその質問で画像をもう一度見ます。回答はトランスクリプトの画像行の下に表示されます。画像リルックは日次 `media.video.rewatch.maxPerDay` カウンターを動画再視聴と共有します。リトライは動画のみに適用されます。

`features.mediaDescriptions`（デフォルト有効）は `vision` モデルを使い、画像、GIF フレーム、動画ポスター、スティッカー、カスタム絵文字、リンクサムネイルに対して一行の説明文を書きます。各添付ファイルは一度だけ記述され、`data/guilds/<id>/media.json` にキャッシュされます。説明文はチャットのトランスクリプト、メモリアナライザー、ウォームアップに供給されます。説明モデルのプロンプトは `prompts/describe.md` です。

スティッカーとカスタム絵文字は頻繁に繰り返されるため、ID でキャッシュされ、初回の記述後はほぼコストがかかりません。`features.vision` が有効な場合、呼び出しメッセージのスティッカーは画像として添付されます。Discord の組み込みアニメーションスティッカーは Lottie アニメーションであり画像ではないため、名前以上の情報は得られません。

`features.gifs` が有効（デフォルト）の場合、`<gifs>` ブロックにメンバーが共有する GIF が使用頻度と新しさでランク付けされて表示されます（最大 `gifs.max`、デフォルト 40）。各 GIF にはハンドル（`g1`、`g2`、...）とキャッシュ済みの 3 つのキャプションフィールド（リアクションラベル（`gifs.reactionChars` で制限、デフォルト 40）、可視アクション（`gifs.actionChars` で制限、デフォルト 70）、画面上のテキスト）が付きます。制限はフィールドが表示される場所（リストおよびライブラリ GIF のトランスクリプト行）で適用され、キャッシュには `media.descriptionChars` の範囲内で完全な状態で保存されます。フィールドのないエントリは単語境界でカットされた一行キャプションを使用します。ペルソナは `<gif>` タグにハンドルを書いて GIF を投稿できます。ターンあたり 1 件。不明なハンドルは無視されます。GIF は `gifv` タイプの埋め込み（プロバイダー問わず）や既知の GIF ホスト（Tenor、Giphy、Klipy）のページから認識されます。GIF ページはリンクとしては読み取られません。使用回数はメッセージ到着時にカウントされます（メンバーのみ、ボットとペルソナは除外）。Discord がメッセージ本体の後に埋め込みを配信した場合（Tenor の GIF はこの方式で届く）、ボットはその埋め込みをバッファに取り込み、ライブラリとアナライザーが GIF を認識できるようにします（`features.embedUpdates`、デフォルトオン）。初回起動時にチャンネル履歴の最後の `gifs.backfillMessages`（デフォルト 500）件を読んでライブラリをシードし、上位 `gifs.backfillDescribe`（デフォルト 20）件にキャプションを付けます。トランスクリプト内でライブラリに含まれる GIF はハンドル付きで表示されるため、ペルソナは見たものを再利用できます。`/nep media kind:gifs action:status` でライブラリのサイズと上位エントリを確認。`/nep media kind:gifs action:rescan` で使用カウントをリセットしチャンネル履歴から再カウント（ハンドルは安定）。

`media.gif.watch` が有効な場合（デフォルト。動画ビジョンも有効である必要あり）、GIF は短い無音クリップとして視聴されます。アニメーションが最大 `media.gif.maxSeconds`（デフォルト 8）秒の mp4 に変換され、`prompts/describe-gif.md` を通じて `video` ロールのモデルに送信されます（ファイルが存在しない場合は `describe-video.md` にフォールバック）。視聴後のキャプションが旧来の単一フレーム記述を置き換えます。視聴できない GIF（アニメーションなし、日次上限 `media.gif.maxPerDay` 到達、変換やリクエストの失敗）は単一フレームの記述を維持します。`/nep media kind:gifs action:recache` はライブラリ外の古い単一フレームキャプションを削除し、バックグラウンドで最大 `gifs.recachePerRun`（デフォルト 50）件のライブラリエントリを古いものから順に再視聴します。

`features.gifPicker` がオン（デフォルト、`features.gifs` がオンでライブラリが空でない必要あり）の場合、分類器がフルライブラリから短い最初のメッセージの代わりとなる GIF を選びます。ピッカーはペルソナの最初の送信メッセージが `gifs.pick.maxChars`（デフォルト 160）文字以下で、自分で GIF を選ばなかった場合に実行されます。分類器は直近のチャット行、その最初のメッセージ、各ライブラリエントリのキャプションを参照します。一致した場合 GIF が最初のメッセージを置換し、元のメッセージと同じ送信先にリプライします。残りのメッセージは順番に続きます。GIF の送信に失敗した場合、すべてのメッセージがそのまま投稿されます。

設定: 直接ビジョンは `context.vision.*`、説明モデルは `media.*`、GIF ライブラリは `gifs.*` 配下にあります。全キーの詳細は[設定リファレンス](configuration.md#media)を参照してください。

## 動画

`features.videoDescriptions` はデフォルトで無効です。`config.local.json` で `mediaDescriptions` と合わせて有効にしてください。有効にすると `video` ロールのモデルが追加され、短いクリップを視聴します。対象は Discord の動画添付ファイル、Discord CDN から貼り付けた動画リンク、既知の動画サイトへのリンク（YouTube、TikTok、VK、X、Reddit、Twitch）です。モデルは OpenRouter を通じて動画と音声の両方の入力を受け付ける必要があります。

### 上限

添付ファイルとダウンロードしたサイト動画は `media.video.maxSeconds`（デフォルト 180 秒）と `media.video.maxBytes` で制限されます（超過するファイルはまずビットレートを制限して 360p に再エンコードされ、再エンコード後も超過する場合のみ拒否）。agentic モード（`urlProcessing`、デフォルト）では、公開 URL 動画（YouTube およびその他の `directUrlSites`）は `directUrlMaxSeconds`（デフォルト 3600 秒、1 時間）までピン留めされたプロバイダーに URL で送信されます。他のモードではこの値と `maxRequestTokens / tokensPerSecond`（デフォルトでは 500 秒）の小さい方が有効です。超過する動画はダウンロードルート（先頭の `maxSeconds` を yt-dlp で取得）へ移行しますが、YouTube はサーバーからのダウンロードをボットチェックでブロックすることが多いです。ターンあたり最大 `maxPerTurn` 件の新規動画（成否を問わずすべての試行がカウント）、1 日あたり `maxPerDay` 件です。結果は画像の説明文と同じキャッシュに保存されるため、再投稿のコストはかかりません。

### ツール

上限内の添付ファイル以外はすべて `yt-dlp` でダウンロードされ `ffmpeg` でトリムされます。どちらもオプションのシステムバイナリです。これらがなくても上限内の添付ファイルはそのまま動作します（そのまま送信されます）。長い添付ファイルとすべてのサイトリンクは静止フレームにフォールバックします。Discord CDN からの動画リンクには再生時間のメタデータがないため、常に ffmpeg を経由します。ffmpeg がない場合は静止フレームにフォールバックします。YouTube の場合、`yt-dlp` が再生時間を取得できないときは、`.env` のオプションの `YOUTUBE_API_KEY`（無料、Google Cloud コンソールの YouTube Data API v3）またはウォッチページのスクレイプが補完します。`/nep status` は API key のステータスを報告します。

### 再視聴

ペルソナに直接話しかけられ（`overheard` や自発的なターンではなく）、すでに視聴済みの動画について質問された場合、分類器（`prompts/rewatch.md`、`analyzer` ロール）が再視聴の必要性を判定します。必要な場合、動画モデルが `prompts/rewatch-answer.md` でクリップを再度視聴し、回答がオリジナルのサマリーと共にトランスクリプトに表示されます。同じ分類器は、読み込めなかった動画について再度問い合わせがあった場合にリトライすることもできます。ターンあたり最大 1 回の再視聴またはリトライ。回答は 1 時間キャッシュされます。スイッチ `features.videoRewatch`（デフォルトオン）。

動画プロンプトは `prompts/describe-video.md` です。設定は `media.video` 配下にあります。全キーとモデル比較表については[設定リファレンス](configuration.md#mediavideo)を参照してください。

## リンク

`features.webLookup`（デフォルトオフ。他の機能と異なり、キーが存在しない場合はオフとして扱われる）を有効にすると、ペルソナはチャットに投稿されたリンクを開いて読み取れます。

機能が有効で `web.links.enabled` が false でない場合、トランスクリプト内のリンク（http/https のみ、プライベートアドレスは拒否、動画サイトリンクは除外、`web.links.skipSites` は除外）は SSRF ガード付きページフェッチャーでフェッチされます（サイズ上限 `web.links.maxBytes`、タイムアウト `web.links.fetchTimeoutMs`、最大 3 リダイレクト、html とプレーンテキストのみ）。ページテキストは `reasoner` ロールのモデルが `prompts/read-link.md` を通じて最大 `web.links.summaryChars` 文字の抜粋に要約します。抜粋はリンクのトランスクリプトタグに `transcript.linkRead` として追加され、ファーストハンドとして表示されます: ペルソナがその抜粋の範囲内でページを自分で開いて読みました。読み取れないページ（ペイウォール、同意画面、ログインゲート、空のコンテンツ）は検出されミスとしてキャッシュされます。URL パスが画像・動画・音声・アーカイブの拡張子（png, jpg, jpeg, gif, webp, avif, svg, mp4, webm, mov, mkv, mp3, ogg, wav, zip, rar, 7z, pdf）で終わるリンクはホストに関係なく読み取られず、`web.links.skipSites`（サブドメインを含む）のデフォルトは Discord CDN、Tenor、Giphy、Klipy、Imgur、Reddit メディア、Twitter 画像です。

`web.links.prefill` が有効（デフォルト）の場合、リンクは到着した時点で読み取られ、次のターンでキャッシュ済みの状態になります。プリフィルはメンバーあたり 1 日 `web.links.prefillPerUserPerDay`（デフォルト 10）で制限されます。ターンパスはこの制限を受けません。ターン中の各フェッチ試行は `web.links.maxPerTurn`（デフォルト 2）にカウントされます。リンク読み取りと検索は日次カウンター `web.maxPerDay`（デフォルト 60）を共有します。`llm.maxRequestsPerDay` を使い切ると、新規のダウンロードもミスとしてのキャッシュも行われません。

読み取り結果はメディアキャッシュに保存されます: `read:<link.id>` が抜粋またはミス（6 時間スキップ）を保持します。`<senses>` ブロックには機能が有効な場合に `senses.linksRead` が含まれ、リンクに読み取り抜粋が付随する可能性があることをペルソナに伝えます。

## 検索

ペルソナに直接話しかけられ（`overheard` や自発的なターンではなく）、トリガーメッセージがチャットにない事実を必要とする場合、分類器（`prompts/lookup.md`、`reasoner` ロール）が何を調べるかを判定します。分類器はウェブ検索、サーバー履歴検索、またはその両方を要求できます。

分類器は `lookup.md` プロンプトが存在し、`features.webLookup` または `features.recall` のいずれかがオンの場合に発火します。回答は最大 4 行のラベル付き行です: `web:` はウェブクエリ、`server:` はサーバーのメッセージを検索するワードフォーム、`who:` は人物を見つけるネームフォーム、`when:` は日付範囲。

ウェブ検索には `features.webLookup` オン、`web.search.enabled` が false でない、`web.search.maxPerTurn` が 1 以上、`.env` に `BRAVE_SEARCH_API_KEY`（無料枠: 2,000 クエリ/月、以降は 1,000 クエリあたり $5）が必要です。結果は `prompts/search-summary.md` で要約され `<lookup>` ブロックに表示されます。Brave キーがない場合、リンク読み取りは動作しますがウェブ検索は動作しません。

サーバー検索には `features.recall` オン（デフォルト）が必要です。エンジンは Discord の検索 API でサーバーのメッセージ履歴を検索し、ヒットを時間クラスターに分類、各クラスター周辺のメッセージウィンドウをフェッチし、サマリーヘルパー（`prompts/recall-summary.md`）に回答を求めます。分類器のワードフォームとネームフォームは保存済みメモリ（エピソード、ロア、レッスン、最近の行。プライベートレイヤーは対象外。最大 `recall.memoryItems`、デフォルト 6）とも照合され、一致する項目は `<memory>` ブロックとしてサマリーに送られるため、古いチャットが見つからなくてもヘルパーにコンテキストがあります。サマリーが特定のストレッチを指定した場合、そのストレッチの原文が `<lookup>` ブロックに表示されます。サマリーが何も見つけなかった場合、サーバーパートは表示されません。リコール実行は `recall.maxPerDay`（デフォルト 100）/日、`recall.timeoutMs`（デフォルト 10 秒）/実行で制限されます。オーディエンスルールに反するチャンネルのウィンドウは除外されます。全キーの詳細は[設定リファレンス](configuration.md#recall)を参照してください。

両方の検索が実行された場合、`<lookup>` ブロックにはそれぞれの見出しとその間にノートが付きます。ターンあたり最大 1 回のウェブ検索と 1 回のサーバー検索。分類器、ウェブ要約、リコールサマリーはそれぞれ `llm.maxRequestsPerDay` にカウントされます。ウェブ結果は正規化されたクエリごとに `web.search.cacheHours`（デフォルト 24）時間キャッシュされます。`<senses>` ブロックには Brave キーが設定されている場合にのみ `senses.search` が含まれます。`senses.recall` はサーバーターンでサーバー履歴検索が利用可能な場合に含まれます。

ウェブ側の設定は `web` 配下、サーバー側の設定は `recall` 配下にあります。全キーの詳細は[設定リファレンス](configuration.md#web)および[設定リファレンス](configuration.md#recall)を参照してください。プロンプトファイルとコードの間のコントラクトは[プロンプトコントラクト](prompt-contract.md)にあります。

## 描画

`features.imageGeneration`（デフォルトオフ、キーが存在しない場合はオン）でペルソナは画像を描けます。`config.local.json` で有効化してください。モデルが `<draw>` タグを出力すると、エンジンが OpenRouter Images API（`roles.drawing`、デフォルト `openai/gpt-image-2.5-flare`）を通じて 1 枚の画像を生成し、ペルソナのテキストの後に独立したメッセージとして投稿します。描くかどうかはモデル自身の判断で、拒否することもできます。ボットにファイル添付権限がないチャンネルでは、描画の感覚行は表示されず `<draw>` タグは無視されるため、何も生成されず課金もされません。

### 上限

インスタンス全体で 1 日 `image.maxPerDay`（デフォルト 50）枚、メンバーあたり `image.maxPerUserPerDay`（デフォルト 50）枚。リクエスト前にチェックされ、送信時のみカウント。ターンあたり 1 枚。`<draw>` タグのシーンテキストは `image.maxPromptChars`（デフォルト 800）にクランプ。ペルソナが画像に含まれ（`self="yes"`）、`image.reference` が `'avatar'` の場合、ボットの Discord アバターがビジュアルリファレンスとして送信されます。

### コスト

課金は画像単位ではなく出力トークン単位です。プロバイダーの `usage.cost` は `/nep draw` で報告されログに記録されます。エンジンが送信前に拒否したリクエスト（日次または個人上限、非対応モデルファミリー）はコストがかかりません。プロバイダーが拒否した生成は通常課金されません。タイムアウト、または画像生成後にアップロードが失敗した場合は課金される可能性があります。画像リクエストは `llm.maxRequestsPerDay` にカウントされません。

### プライバシー

描画プロンプトはメンバーを引用する可能性があります（モデルが書いたシーンテキストが会話を参照することがあるため）。ログにはカウントのみが記録され、プロンプト自体は記録されません。ドライランでは完全なイメージプロンプトがログとドライランチャンネルにミラーされますが、何も生成されません。

### 失敗

リクエストされたターン（メンション、リプライ、名前トリガー、フォローアップ）で描画が失敗した場合、トリガーラベルに失敗理由を含む 2 回目のターンが発火し、ペルソナがリクエスト者に何が起きたかを伝えられます。2 回目のターン自体の `<draw>` は無効化されます。自発的ターンや `overheard` ターンでは失敗はログに記録されるだけです。画像上限（日次またはメンバー上限）は失敗ターンを発火せず、リクエストされたターンではリミット通知（`labels.limits.notice`）を投稿し、どのリミットと数値を示します。

設定は `image` 配下にあります。全キーの詳細は[設定リファレンス](configuration.md#image)、サポートされるモデルは[設定: 画像出力](configuration.md#画像出力imagemodel)を参照してください。

## 盲点

ボイスメッセージは長さのみ表示されます。音声ファイルは名前と長さが表示されます。ペルソナはどちらも聞くことができません。盲点をどう扱うかはキャラクターカード次第です。

## コスト

各ターンは一つの LLM リクエストで、メモリ更新が二つ目を追加します。動画説明文は視聴したクリップごとに `video` ロールへ 1 リクエストを追加します（`media.video.maxPerDay` で 1 日の件数を制限）。`yt-dlp` と `ffmpeg` はローカルで実行され、帯域幅以外のコストはかかりません。リンク読み取り、ウェブ検索、サーバー検索は `analyzer` と `reasoner` ロールへのリクエストを追加し、`web.maxPerDay`（共有、ウェブ側）、`recall.maxPerDay`（サーバー側）、`llm.maxRequestsPerDay`（グローバル）で制限されます。ウェブ検索にはさらに Brave Search キーが必要です。無料枠で低トラフィックのサーバーに対応できます。サーバー検索は Discord の組み込み検索 API を使用するため費用はかからず、分類器とサマリーの LLM リクエストのみ発生します。画像生成は `roles.drawing` を通じて出力トークン単位で課金され、`image.maxPerDay` でチャットリクエストとは別に日次件数を制限します。

## プライバシー

`features.webLookup` が有効な場合、ボットはページ読み取りと Brave Search API への送信 HTTP リクエストを行います。ページはホストから直接フェッチされます。プライベートアドレス（ループバック、リンクローカル、プライベート範囲）は拒否されます。ページコンテンツは要約のために LLM エンドポイントを通じて `reasoner` ロールのモデルに送信されます。ページテキストも検索クエリもログに記録されません。`data/` にはキャッシュされた抜粋と検索結果がマシン上に保存され、gitignore 対象で、LLM にはコンテキストとしてのみ送信されます。
