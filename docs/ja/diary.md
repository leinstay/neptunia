# 日記

ペルソナが一つのチャンネルにランダムな時間に自分で投稿します。誰にも頼まれません。投稿は個人フィードのような形式です: ペルソナの世界のシーンの絵、ミーム、考察、ニュースの要約、豆知識、一行の気分。各投稿の前にペルソナは自分の履歴を確認し、まだやっていないことを選びます。オーナーがチャンネルを指定し、設定でスケジュールと種類を調整します。

## セットアップ

1. サーバーにチャンネルを作成します。ボットには View Channel、Send Messages、Read Message History、Attach Files の権限が必要です。
2. `/nep diary set <channel>` を実行します。コマンドは権限を確認し、`diary.channelId` を `config.local.json` に書き込み、履歴が空の場合はそのチャンネルのペルソナの過去の投稿から埋めます。
3. 日記は次のティック（30 秒ごと）から投稿を開始します。最初の投稿は次のスロットがいつ来るかによって数分かかることがあります。

`/nep diary show` は今日の計画を表示します: チャンネル、`bot.timezone` でのスロット、今日使った投稿数と画像数、履歴サイズ。

`/nep diary off` はチャンネルをクリアします。履歴ファイルは残るので、再有効化で過去の投稿の記憶を保持します。

`/nep diary post [kind] [topic]` は計画外に今すぐ 1 投稿を強制します。ターンが実行中の場合、コマンドは `diary.forceWaitMs`（120000 ms、2 分）まで完了を待ちます。待機がタイムアウトすると `busy` と応答します。日次上限は適用されます。種類キー（例: `selfPicture`, `thought`）はオプションでプランナーの選択を上書き。不明な種類は一覧とともに拒否されます。フリーテキストの topic はオプションで、投稿の題材を指定します。

## ウィンドウ

投稿時間はウィンドウから引かれます: 各ウィンドウは `bot.timezone` の時間範囲で `[min, max]` の投稿数を持ちます。`to` が `from` より後でないウィンドウは午前 0 時をまたぎます。各ウィンドウについてスケジューラーは `min` と `max` の間の整数を引き、その数のスロットをウィンドウ内のランダムな時間に配置します。`diary.minGapMinutes`（90）より近いスロットは削除され、`diary.maxPerDay`（3）を超える場合はランダムに削除されます。

デフォルトの 4 ウィンドウ（すべて `bot.timezone`）:

| ウィンドウ | 時間 | 投稿 |
|---|---|---|
| 朝 | 07–11 | `[0, 0]`（オフ） |
| 昼 | 12–16 | `[0, 1]` |
| 夕方 | 18–01 | `[0, 2]` |
| 夜 | 01–05 | `[0, 1]` |

`diary.quietDayChance`（0.3）の確率で一日中スロットなしになります。計画はローカル日（`bot.timezone` の日付）ごとに 1 回作成され、`data/state.json` に保存されます。新しい日には新計画が作られ、再起動では既存の計画が保持されます。

`diary.slotGraceMinutes`（30）を超えて逃したスロット（ボット停止中）は削除され、遅延発火しません。ビジーなアテンションにブロックされたスロットは猶予内で次のティックにリトライされます。

## 投稿のコスト

各日記投稿は 2 つのモデルリクエストで構成されます:

1. `reasoner` ロールでの計画リクエスト: 種類、一行の概要、検索するかどうか、描画するかどうかを選択。
2. `voice` ロールでのキャラクターカードと全メモリブロックによる作成リクエスト。

計画がウェブ検索を要求した場合（`diary.searchKinds` のみ、デフォルトは `news` と `facts`）、Brave 検索が先に実行され、3 番目のリクエスト（`reasoner` ロールでのコンデンサー）が追加されます。検索は `web.maxPerDay` にカウントされます。

投稿に画像が含まれる場合、画像モデルが独自の価格で生成します。日記の画像は `image.maxPerDay` と `diary.maxPicturesPerDay`（2）の両方にカウントされます。

日記投稿のすべてのモデルリクエストは `llm.maxRequestsPerDay` にカウントされます。デフォルト設定（1 日 1–3 投稿、各 2–3 リクエスト、最大 2 画像）では、1 日あたり約 3–9 チャットリクエストに画像生成が加わります。

## 種類とシード

`diary.kinds` は各種類キーを重みにマッピングします。プランナーは重みと最近の `diary.historyPosts` 投稿で各種類が何回使われたかを見るため、使用頻度の低い種類を好みます。重み 0 の種類は選ばれません。キーとデフォルト値:

| 種類 | 重み | 内容 |
|---|---|---|
| `selfPicture` | 3 | ペルソナがシーンに登場、毎回新しい設定 |
| `picture` | 2 | ペルソナなしの絵: 場所、動物、ここにいる誰かに関するもの |
| `meme` | 1 | ペルソナが描いたミーム |
| `thought` | 2 | 長めの考察、レビュー、意見 |
| `people` | 2 | サーバーの一人についての投稿: 最近の言動、ペルソナがその人をどう思っているか |
| `news` | 2 | サーバーの人々が関心を持つインターネットで見つけたもの |
| `facts` | 1 | 豆知識、氷山エントリ、陰謀論として語られる陰謀論 |
| `status` | 3 | 一行: 気分、計画、退屈 |

`diary.searchKinds`（デフォルト `["news", "facts"]`）は検索をトリガーできる種類。`diary.pictureKinds`（デフォルト `["selfPicture", "picture", "meme"]`）は日次の画像上限が許す限り常に画像付きになる種類。プランナーの回答に関わらず適用される。その他の種類はプランナーが求めた場合のみ描画する。投稿が画像を含められない場合（日次の画像上限が消費済み、描画がオフ、画像モデルがない、またはボットが日記チャンネルで Attach Files 権限を持たない）、プランナーにはテキスト種類のみが提示される。`/nep diary post` で画像種類を強制すると、リクエスト前に拒否される: 上限が原因の場合は上限とその数を表示し、それ以外の場合は `pictures` と表示される。

`prompts/diary-seeds.md` は `# family` ヘッダー（place, setting, detail, activity, subject, twist）でグループ化されたランダムシードを含みます。コードが各ファミリーから 1 行ずつ選び、`diary.seedSets`（2）組み合わせを `<seeds>` ブロックとしてプランナーに渡します。組み合わせはほぼ無限。プランナーはそこから日記の履歴にないものを構築するか、サーバーの生活がより良いアイデアを提供する場合は無視します。

シードをカスタマイズするには `prompts/diary-seeds.md` を `prompts.local/diary-seeds.md` にコピーして行を編集します。ヘッダーの下の各行が 1 つのシード。空行は無視されます。

## ペルソナの世界

`prompts/world.md` はペルソナの仮想世界を記述します: チャット外の場所と日常。追跡ファイルはニュートラルな例。独自に書くには `prompts.local/world.md` を作成します（`appearance.md` と同様に追跡ファイルを丸ごと置き換えます）。

世界ブロックは日記の 2 つのリクエスト（計画と作成）にのみ、`diary.world === true`（デフォルト `false`）の場合のみ表示されます。`/nep set diary.world true` でオン。なしの場合、ペルソナは固定の住居を持たず、主張しません。

世界ファイルは通常のチャットターンには表示されません。ペルソナが `<draw>` タグに書くシーンテキストが画像モデルに必要な情報を運びます。
